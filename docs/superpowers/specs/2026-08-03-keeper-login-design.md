# BluffBook 记账员登录设计

## 目标

取消单独使用 `?keeper=1` 的记账员入口。所有人统一打开 BluffBook 的公开网址，记账员通过页面内的登录入口获得记账权限。报名功能不需要登录。

## 使用流程

- 所有人统一打开 `https://bluff.chengzhuo.work/`。
- 页面顶部显示当前模式。在普通查看模式下，点击该位置会打开记账员登录窗口。
- 记账员输入预先设置的口令，由服务器验证并向当前浏览器发放记账员凭证。
- 登录成功后，页面解锁开局、清空报名、添加玩家、修改买入、填写剩余筹码和账目结清等操作。
- 记账员可以主动退出记账员模式，页面随即恢复为实时查看模式。
- 登录成功后，当前浏览器会记住记账员身份，刷新页面不需要重复输入口令。

## 权限划分

普通用户无需登录，可以：

- 查看实时报名名单和当前牌局；
- 给自己报名；
- 取消当前浏览器发起的报名，不能取消其他人的报名；
- 查看牌力规则和已有的历史内容。

只有记账员可以：

- 根据报名名单手动开局；
- 清空全部报名；
- 添加或删除玩家；
- 修改买入和最终剩余筹码；
- 生成结算并将牌局结清。

服务器 API 是最终的权限判断方。仅仅在网页上隐藏按钮不算真正的权限保护。

## 服务端验证

- 口令仅保存在 Vercel 环境变量 `KEEPER_PASSWORD` 中，不写入公开网页代码。
- `POST /api/game` 接收口令和当前浏览器新生成的凭证。
- 口令正确时，API 将该凭证设为当前记账员凭证，同时保留正在进行的牌局数据。
- API 的响应不会返回服务器中保存的口令。
- 后续修改本局数据仍然必须携带有效的记账员凭证。
- 新设备使用正确口令登录后，会替换旧设备的记账员凭证。因此换手机或清理浏览器数据后仍能恢复权限。
- 未配置口令或口令错误时，API 返回 `403`，页面显示容易理解的错误提示。

## 浏览器状态

- 不再把网址参数作为正常的记账员登录方式。
- 登录成功后，将记账员凭证和模式状态保存在当前浏览器的 `localStorage` 中。
- 退出登录时，同时删除本地记账员凭证和模式状态，并立即隐藏所有记账操作。
- 如果修改数据时服务器返回 `403`，页面自动退出记账员模式，并重新获取线上牌局数据。

## 页面交互

- 现有的模式标记改为可以点击的模式控制按钮。
- 普通查看模式下，点击后打开简洁的口令输入弹窗，包含取消和登录操作。
- 记账员模式下，点击后可以退出记账员模式。
- 登录表单支持按回车提交、登录中的加载状态、口令错误提示、自动聚焦输入框和手机安全区域。
- 公开页面不展示特殊记账员链接、配置说明或记账员口令。

## 部署配置

- 在 Vercel 的 Production 和 Preview 环境中配置 `KEEPER_PASSWORD`，实际口令不写入仓库。
- 环境变量生效后重新部署项目。
- 更新 README，改为介绍统一网址和页面内登录流程，但不公开实际口令。

## 验证项目

- 未登录时，报名和取消自己的报名可以正常使用。
- 未登录用户无法通过页面或 API 修改牌局数据。
- 输入错误口令不会解锁记账操作。
- 输入正确口令后可以进入记账员模式并修改牌局。
- 刷新页面后记账员状态仍然保留，退出后恢复普通查看，再次登录可以恢复记账权限。
- 部署过程中不修改现有报名、当前牌局和历史数据。
